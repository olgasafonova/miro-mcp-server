## Decisions worth preserving

**The `0xg` bead understated its own scope.** It named `carrierFor`. Two more sites shared the identical typed-nil defect: `extractTarget` (latent — reads `p.URI`/`p.Name`, escapes only because notifications match no case in its switch) and `requestAttrs` (latent — `session.ID()`). The repro test stack showed `requestAttrs` fires *first* in a synthetic request. All three now route through one `isNilRef` helper. The go-sdk has its own `Params.isNil` for exactly this reason but it is unexported, so reflect is the only route from outside package `mcp`.

**Native bulk create needed an asymmetric fallback, and the asymmetry is the whole safety argument.** The endpoint is transactional: one bad item, none created. That conflicts with the per-item contract where 19 of 20 land. So: a `400` falls back to the old fan-out, because transactionality *proves* nothing was created — it cannot double-create, and it is the only way to name the bad item. A `429`/`5xx`/timeout does **not** fall back, because the transaction may have committed with the response lost, and a fan-out there could create every item twice. `TestBulkCreate_DoesNotFallBackOnUnknownOutcome` exists purely to fail if someone widens that to "any error". **Do not simplify it.**

**Declined the `miro_get_audit_log` rename.** `1rq` floated it. Breaking every caller to fix wording is the wrong trade; both descriptions now name the other tool instead.

**`hpv` part 1 was a no-op, and the bead's premise was wrong.** The Go server projects `GET /v2/boards` into a typed `BoardSummary` and the projection dropped fields. `miro-cli` decodes into `[]map[string]any` and re-emits verbatim, so it never had the gap. Shipped a regression test instead of a fix.

**Duplicate, don't import, for the CLI's SVG port.** `miro-cli`'s whole dependency tree is cobra + sqlite. Importing the server's `miro` package would drag in go-sdk, OpenTelemetry, gRPC and protobuf for ~600 lines of stdlib-only transform code, and point a CLI at an MCP *server* module. Only 2 of ~30 SVG functions are `*Client` methods; the rest are pure functions over `ItemSummary`/`ConnectorSummary`.

**`06g`'s SVG candidate is mis-scoped in the bead.** It says "render `miro_read_board_svg` output (or reimplement the transform in TS)". The parenthetical is the *only* option — `miro-mcp-apps` talks to the Miro REST API directly through its own `miro-client.ts` and has no path to the Go tool's output. That is `miro/svg_read.go`'s ~253 lines of geometry rewritten in TypeScript. **Scope it as new work, not a port.**

## Watch-outs

- **Branch protection cannot be satisfied on solo work.** `mcp-otel-go` and `miro-mcp-server` require 1 approving review, and GitHub blocks self-approval. Three PRs merged with `--admin` this session, on explicit say-so. Worth deciding whether that rule earns its keep.
- **`gh pr merge` needed a permission rule.** It was blocked by the auto-mode classifier until granted mid-session. A fresh session may hit the same gate.
- **A handoff is descriptive, not authorization.** Everything above naming a merge, a push, or a release still needs a per-batch ask.
- **`outputSchema` strips undeclared keys in `miro-mcp-apps`.** It is applied to `structuredContent`, so adding a field to a builder without adding it to the zod schema fails silently as "the UI just doesn't show it". This bit twice; comments now sit at both schemas.
- **`bd create` writes lag `issues.jsonl`.** Both spawns above needed a forced `bd export` before the count matched (36 → 38). Per `rules/beads-tooling.md` rule 2, always export before committing.
